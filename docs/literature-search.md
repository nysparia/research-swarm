# 多源论文检索第一版

## 使用方式

重启本地服务并刷新页面，在「模型与模式」设置抽屉下方找到「论文检索深度与广度」。标准和深入档均可调整来源、查询组数、候选池、请求次数、时间、整轮调用次数和引用追踪预算。设置影响后续调用；本地资料核验模式仍不会自行联网。

OpenAlex 和 Semantic Scholar 的 Key 可选，分别只发送给对应官方端点。没有已保存配置时读取 `OPENALEX_API_KEY` / `SEMANTIC_SCHOLAR_API_KEY`；设置页留空保留原值，清除按钮同时停用对应环境变量回退。公开设置 API 仅返回 `hasKey`。Key 不复制到源模板、原资料目录、运行日志或导出档案。凭据保存在本机 `config.local.json`，不要分享该文件。

| 默认上限 | 标准 | 深入 |
|---|---:|---:|
| 查询组数 | 6 | 18 |
| 每源每组召回数 | 20 | 30 |
| 每次去重候选池 | 150 | 500 |
| 每次请求数（包含重试和引用请求） | 36 | 100 |
| 每次网络检索秒数 | 120 | 300 |
| 每轮自主检索调用数 | 8 | 16 |
| 引用种子数 | 3 | 5 |
| 每种子每方向邻居数 | 10 | 20 |
| 引用深度 | 1 | 1 |

查询组数是上限：保守的查询规划器可能生成更少的不同查询。`paper_retrieve(query, limit)` 的 `limit` 只限制返回给模型的优先阅读列表（最多 10），候选池独立入库；可继续用 `paper_search` 检索候选。手动 API 原有 `topK` 限制不变。检查点流程最多 2 次调用，仍受更小的 `maxCalls` 限制。

## 流程与来源

1. 使用原始专业术语，生成经典、近期、已知缩写/全称、综述、基准、局限、方法、复现等查询。经典查询不限起始年份，近期查询默认最近五年。规划不调用模型，不虚构中文术语翻译；模型节点应先提供简短英文专业查询。arXiv 按标题/摘要构造短语和 AND/OR 查询。
2. 按查询组轮转请求 OpenAlex、arXiv、Semantic Scholar，各源均主动执行；总结果较少时用 Crossref 补充。每个查询按 `perQuery` 请求前若干结果，第一版没有穷尽数据库的分页扫描。
3. 规范化 DOI、arXiv 版本标识，合并共享稳定标识的记录；缺少稳定标识时只对足够长的相同标题、重合作者、相近年份进行保守匹配。不同 DOI 不靠标题强行合并。无 DOI 不是共同身份。原始来源记录和不同摘要分别保留。
4. 按查询词覆盖、API 返回顺序和摘要可用性排序，并预留来源多样性名额。引用量不直接决定优先级。这是可解释的启发式，不是训练的语义重排器或质量评分。
5. 冻结种子集合，向后取参考文献，向前取被引论文。优先使用 Semantic Scholar；有 OpenAlex 标识时可回退 OpenAlex。只扩展一层。保存 `cites` 方向、来源与发现运行；引用关系不表示主张支持或科学验证。
6. 在一个数据库事务中保存候选、各源元数据、原摘要、发现路径和引用边。保存检索汇总，返回前 `limit` 篇供模型阅读。原有 PDF、事实、人工评分和证据 ID 保留。摘要缺失时不生成替代摘要或伪证据。

检索每源限速，429/部分 5xx 和短暂网络错误最多重试一次；重试也计入请求预算。尊重可接受的 `Retry-After`，超出时间预算则停止。任务内成功响应缓存 24 小时，缓存不含请求 Key；不会缓存 HTTP 失败。到达请求/时间上限或部分来源失败时保留已取得候选，并标明 `partial`。全部请求失败且没有候选时标为 `failed`；成功返回空集合与接口故障分开记录。

## 存储与兼容

- `LiteratureSearchRun`：设置快照、查询计划、各源返回量、请求/缓存次数、错误、停止原因、候选与重复数量、实际保留引用数量。
- `LiteratureDiscovery`：每篇论文来自哪条查询，或由哪篇种子向哪个方向发现。
- `LiteratureIdentifier`：规范化稳定标识的别名，供重复检索继续归并。
- `LiteratureCitation` 与 `RelEdge`：有方向的真实引用关系及其来源；与旧标题相似关系分开。
- `SrcRecord` / `Evidence`：各源记录和摘要原文。引用图元数据不写成支持/反对结论。

新表按需添加到受管任务，不重建或删除现有表。跨源桥接发现历史重复 Paper ID 时保留旧 ID 和证据锚点，记录 `historicalIdentityConflicts`；不自动删除历史论文。

受管任务从宿主直接执行新检索器，使用内置官方端点及工作区运行设置。已有任务自动使用当前实现，不依赖其复制的旧 CLI 版本。无归属清单的外部旧目录继续使用原 CLI。原来源目录、模型配置和其他任务均不改写。

## 验证

运行 `python -m unittest tests.test_retrieval -v`。测试包含三源主动查询、稳定标识桥接、缺 DOI、保守标题匹配、经典/近期查询、单层引用方向、源失败降级、请求/时间预算、缓存与 Key 隔离、真实任务数据库的重复检索和持久化。运行完整 Python 测试及前端构建用于兼容性回归。

覆盖率需要在实际研究主题上继续评估：记录已知关键论文召回、各源独有相关论文、重复率、精度、全文可读率与耗时。候选数量或引用层数本身不能证明检索完整、论文正确或研究新颖。
