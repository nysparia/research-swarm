# Conversation-only v2：契约与兼容验收标准

本文定义新后端的业务边界；具体请求示例与已支持操作以 [后端工作台 API](backend-workspace-api.md) 为准。`legacy` 与 `conversation_only_v2` 是任务级选择，不是对已有任务的隐式数据迁移。

## 三个独立职责

1. **对话理解**：根据用户消息整理研究草稿、说明理解、识别核心歧义。不进行研究性检索或实验，不作执行授权。
2. **研究契约确认**：用户确认具体 Brief 版本，锁定研究目标、交付物、范围、证据要求和执行政策。确认与开始运行是两个动作。
3. **研究执行**：Run 固定引用确认契约。调度器选择允许的阶段，Agent 在已授予的工具能力内工作；模型建议不能自行升级为执行命令。

Markdown 是可阅读的投影，不是第二份契约事实源。旧 `researchCycle`、`researchDecision` 只属于 legacy 和历史记录，不能成为新运行的控制协议。

## 状态与版本

- `briefDraft` 可以随需求讨论产生新版本；`confirmedBrief` 记录用户确认的具体内容。
- 草稿更新后，旧确认不能启动新运行。已开始运行的契约不因新草稿变化而改写。
- 需求状态与运行状态分开。任务可以同时有正在执行的旧 Run 和尚未确认的新草稿。
- Run、节点和异常分别有并发检查版本；领取节点还需要执行代际与令牌。
- 重复启动请求不得重复创建运行；同一幂等键对应不同请求内容时必须冲突。
- 取消、暂停、重启或替代后的迟到输出可保留为历史，不得重新成为当前结果。

## 接口兼容原则

| 原有入口 | 新流程的兼容要求 |
|---|---|
| `POST /api/tasks` | 增加可选 `workflowVersion`；未提供仍创建 legacy |
| `GET /api/tasks`、`GET /api/tasks/{id}` | 继续使用原入口，合并新旧任务；保留兼容详情字段并补充版本/能力信息 |
| `POST .../messages` | 保留文字消息入口；研究中普通消息只解释结果，不等同改范围或解决异常 |
| `GET .../document` | 可提供只读 Markdown 投影，不赋予写契约能力 |
| `POST .../start` | 如提供兼容别名，必须进入与新启动入口相同的确认、版本和幂等检查 |
| `GET .../workbench`、`report`、`events`、`events/stream`、`export` | 优先沿用 URL，按任务版本选择读模型和事件来源 |
| `POST .../document`、`research-choice` 等旧写入 | legacy 保持原行为；v2 不允许绕过契约与类型化异常，返回明确错误 |
| `POST .../jobs` 及实验工具 | 不得因是旧入口而绕过已确认的实验权限 |

仅在旧接口无法准确表达语义时增加 Brief 读取/确认、运行绑定和异常解决等入口。兼容的是调用形状与合理行为，不是绕过安全边界的能力。未知 workflowVersion 不得静默回退到 legacy。

## 权限不是提示词

同一份冻结执行政策需要在计划接收、节点调度和工具调用处检查：

- 没有确认契约，不启动研究性检索、实验或多 Agent 运行。
- 禁用实验时，不创建实验节点，也不能直接调用 Python 执行或安装工具。
- 禁用复现时，发现复现价值只能写入可选后续建议。
- 所有主线节点绑定契约内目标；可选成本、凭据或新机制建议不能自行成为主线。
- 代码阅读只针对用户明确提供的材料，不允许任意宿主文件路径。
- 工具预算、执行设置和材料版本固定到 Run；后续任务设置不能静默扩大已运行权限。
- 允许运行 Python 仍不等于操作系统安全沙箱。现有进程管理、独立目录与虚拟环境不提供完整文件/网络隔离。

结构校验能阻止非法目标 ID 和工具越权，但不能机械证明所有自然语言内容都语义忠实。报告应保留可追溯依据和限制，而不是宣称绝无范围偏差。

## 异常与不确定性

固定异常类型为 `scope_change`、`missing_core_input`、`identity_ambiguity`、`credential_required`、`cost_or_resource_required`、`irreversible_action`。

Agent 的 `exceptionRequest` 只是请求。后端必须核对实际依赖、契约和可执行动作，再判断是否受理、是否阻塞主线。模型返回 `blocking=true` 不能直接取得全局暂停权。

普通资料缺失、证据冲突和不能下定论属于研究结果。可选分支缺凭据不应暂停可继续的主线。异常处理选项由宿主定义，不能执行模型写出的自然语言 effect；解决异常也不能原地扩大运行权限，需要修改范围/权限时重新确认契约。

## 数据、恢复与历史

Brief、Run、Exception、消息和领域事件使用事务型事实源；展示投影可重建，不参与裁决确认版本。领域变更与事件同事务，SSE 可按领域游标重放。

外部副作用不能由 SQLite 单独保证恰好一次。工具调用须记录开始、回执和结果；重启后结果不明的实验不得自动重放。运行恢复必须显式，断点续跑必须有真实断点和恢复协议。

旧任务保留可读。导入旧需求到 v2 默认生成未确认草稿；没有确切授权记录时，不把旧 requirements 推断成新权限的用户确认。旧决策保留为历史，不能自动接续成当前异常。

## 核心验收

- 未确认不能研究；过期确认不能启动新 Run。
- 问答不改契约；明确范围变更仅产生新草稿。
- 模型不能创建越权节点、调用越权工具或用旧控制字段暂停运行。
- 没有实测、来源不明、哈希不符或审阅缺失，不得伪装成已验证结论。
- 并发确认/编辑/启动、重复请求、迟到结果和重启不破坏版本边界。
- v2 完成端到端研究时不构造旧 Engine；legacy 现有测试继续通过。
- 原有公共读取接口和任务详情尽量兼容，所有旧写入口都经过相应版本的边界检查。
