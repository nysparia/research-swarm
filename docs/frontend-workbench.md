# Tailwind 研究工作台

新版入口位于 `/`，继续使用既有的本地任务、模型配置和研究引擎。

## 主要交互

- 左侧仅保留科研任务列表与模型设置。新建任务后，用自然语言说明问题。
- 准备阶段同时显示对话和可编辑 Markdown 需求。保存后可预览整理结果，再开始研究。
- 研究看板按批准的 Part 3 原稿排列：左侧大对照卡，右侧主张和实验终端，下方当前产出与研究摘要。头像展示实际节点当前活动。没有实测数据时显示待补充状态。
- 右侧常驻目标、边界、验收三块草稿摘要；点击摘要或「编辑草稿」打开完整编辑抽屉。研究中的修改先展示服务端计算的影响，再确认应用。完成态通过任务菜单编辑草稿，未确认编辑会阻止换任务或继续对话并自动打开编辑抽屉。
- 点击卡片旁的讨论入口打开局部气泡，提供「追问 / 沿此深入」。普通询问只解释；深入、质疑和修改生成明确提案。回复绑定产物版本。
- 实验室可提交 Python 实验，导入文本、文件、本机目录或固定版本代码仓库，配置后续实验材料与资源。运行结果包含 stdout/stderr、指标、脚本、执行历史、下载文件及回执。
- 历史产物只显示该版本保存的内容，不能操作当前作业。续跑要求真实检查点与恢复代码。
- 研究过程保留二维结构、检索统计、节点输入输出与完整活动，入口位于任务菜单。论文模块按实际能力和产物出现。
- 完成态左侧研究报告、右侧真实交付文件与下一步操作。报告可逐条查看证据链。导出保留原有研究档案；下一轮对话回到需求准备阶段。

桌面使用大看板与窄笔记栏；窄屏通过任务菜单与折叠笔记保留主工作区。新增内容和状态局部模糊入场，遵循系统减少动态效果设置。

## 本次修复的执行问题

Windows 深层目录中，原子写入的临时文件路径可能超过传统路径限制，导致实验回执保存失败、作业滞留运行态。文件操作现在使用 Windows 扩展路径；回执失败会记录失败原因、保留实际日志并继续调度后续作业。回归覆盖长路径和写入失败两种情况。
