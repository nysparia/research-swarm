# Tailwind 研究工作台

新版入口位于 `/`，继续使用既有的本地任务、模型配置和研究引擎。

## 主要交互

- P1：任务侧栏与中心输入框。第一次发送才创建任务，失败时保留输入。侧栏收纳资料库、实验环境和模型设置。
- P2：左侧持续对话，右侧完整 CodeMirror Markdown 编辑器，支持标题、列表、表格、代码、撤销、查找与 GFM 预览。自动保存和 AI 整理沿用文档版本；切换任务与开始研究须等待当前编辑保存完成。
- P3：左侧对话，右侧为完整 agent 结构，没有看板/表格/草稿切换页。节点内显示其实际主张、证据、协议、指标、实验状态和日志。保留真实父子与回传关系，支持拖动画面、缩放、缩略图和节点定位。
- 节点的「从这里深入」将节点、产物和版本加入主输入框；可先讨论，也可选择深入研究。研究变更由服务端预览影响，再确认应用。任务切换保留尚未发送的文字、节点引用与操作类型。
- 普通询问串行处理并写入主对话，排队、失败、重试和回复都可追踪。历史版本的回复保持原引用；过期的研究修改必须重新计算影响。
- 实验室可提交 Python 实验，导入文本、文件、本机目录或固定版本代码仓库，配置后续实验材料与资源。运行结果包含 stdout/stderr、指标、脚本、执行历史、下载文件及回执。
- 历史产物只显示该版本保存的内容，不能操作当前作业。续跑要求真实检查点与恢复代码。
- 节点详情、完整运行记录、历史检查点、研究产物和需求修改位于节点入口或任务菜单。
- P4：持续对话与实际研究产物并列。研究记录、报告、论文草稿、材料与证据分开呈现；只有真实论文产物存在才显示论文草稿。下一轮通过显式入口返回需求准备。

桌面使用持续对话与独立工作区；工作区可收起。窄屏切换对话/工作区，任务导航覆盖展开。样式以 Tailwind 和中性 CSS 实现，抽屉与确认弹窗继续使用 Ant Design；动效遵循减少动态效果设置。

## 本次修复的执行问题

Windows 深层目录中，原子写入的临时文件路径可能超过传统路径限制，导致实验回执保存失败、作业滞留运行态。文件操作现在使用 Windows 扩展路径；回执失败会记录失败原因、保留实际日志并继续调度后续作业。回归覆盖长路径和写入失败两种情况。
