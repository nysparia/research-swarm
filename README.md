# 科研蜂群 · 本地研究编排与证据审阅

Windows 双击 **start-research.cmd**；Linux 在项目目录运行 `bash start-research.sh`。打开 [本地科研工作区](http://127.0.0.1:4381)。默认可使用离线的已有材料核验；在模型设置中分别配置生产、裁判和红队，再明确启用模型推理。

这是研究编排工具，名称中的「蜂群」不代表默认存在异质智能体。单模型可以整理资料、规划和执行任务；主张定论需要单独配置裁判，实验验收需要单独配置红队。**默认远程端点意味着本地编排 + 云端推理，不是数据不出机。** 单元测试、模型复核和用户签名都不等于科学验证。逐项状态见 [问题整改与验收边界](docs/audit-remediation.md)。

## 使用流程

1. 新建科研任务，用自然语言描述问题，编辑生成的 Markdown 需求。草稿自动保存，版本冲突保留用户原稿。
2. 选择「探索研究」或「复现预检与小实验」。模型明确背景、文献、课题和可证伪主张，再分解取证、设计和执行任务。
3. DOM + SVG 二维层级图显示主张与任务，可平移、缩放、拖动。点击主张查看原文、定位符、方向、范围、版本和日志；预览修改的影响范围后重跑相关分支。
4. 对话显示过程和候选结果。AI 辅助定位需审阅的材料，重要判断仍需用户检查原文、方法和适用条件。
5. 查看产物、下载研究档案，或继续下一轮；旧证据、版本和执行历史保留。研究中可暂停或修改方向。

界面使用 React / Ant Design，支持减少动态效果设置。默认自主流程不要求最终确认弹窗才能导出；使用检查点流程或明确确认主张时，需要责任签认。

## 安装、资料与隐私

随仓库交付 `dist/`，正常使用不需要 Node.js。需要 Python 3.10+；启动脚本在项目 `.venv` 安装依赖。Linux 需要 Bash、Python venv 和 pip，可通过 `RESEARCH_SWARM_PYTHON=/path/to/python3.10 bash start-research.sh` 指定解释器。脚本前台运行，Ctrl+C 停止；`bash start-research.sh --help` 查看参数。前端开发需要 Node.js 20.19+ / 22.12+。

默认使用 `vendor/ai-access` 无密钥检索模板，从空任务开始，不依赖作者机器的资料目录。可用 `--source "资料目录"` 或 `RESEARCH_SWARM_SOURCE` 指定导入源，原资料只读。公开检索通过 OpenAlex，必要时回退到 Crossref / arXiv，不需要检索服务 Key。PDF 读取保留指纹和页码；缺全文、扫描页、下载失败均保留原因。文件存在不等于已经阅读或复现。

服务只监听 `127.0.0.1`，前端与 API 同源。各任务的对话、需求版本、SQLite、PDF、节点和产物独立保存在 `.research-state/tasks/<任务ID>/`。Key 保存于 `.research-state/config.local.json`，不通过配置查询 API 回传、不进入报告导出；**调用远程模型时仍会作为鉴权信息发给服务商，主张、证据和实验材料也可能进入请求。** 请勿分享状态目录。

| 槽位 | 职责 | 未配置或调用失败 |
|---|---|---|
| main | 需求、检索、规划、代码和研究草稿 | 可切换已有材料核验；模型任务保留错误 |
| judge | 盲审主张及原始证据 | 保留证据，判断为未复核/证据不足 |
| redteam | 检查当前实验协议、脚本和原始数据 | 保留产物，实验不接收为有效实测 |

旧 `provider` 配置迁移为 main。生产槽保留 DeepSeek 默认值和 `DEEPSEEK_API_KEY` 支持；默认值不保证服务当前可用，应逐角色测试。裁判、红队初始为空，不继承主模型，不静默回退。端点与模型标识不同只证明配置可区分，不能证明厂商、模型族或统计独立性；需要自行配置并校准不同来源。

设置页提供本机 OpenAI 兼容端点预设（Ollama `http://localhost:11434/v1`）；模型须事先在本机部署并测试连接。仅当所有推理端点均在本机且未执行外部检索、下载或依赖安装时，才是纯本机路径。断网使用已有材料核验时，可保存草稿、核验现存资料、查看缺口；该模式不会自动调用模型或联网补充检索。

## 证据判定与确认

持久化 `claimGraph` 区分主张、证据关系与研究表达。关系包含支持、反对、混合、未定及适用条件；同一来源重复引用不会算成独立验证。

judge 只接收主张原文、原始证据及量规，不接收生产者摘要、旧结论或理由。方向关系必须附原文片段、实际定位符、白名单模式和置信度。宿主检查引文锚点、支持模式与凭据完整性，**不能靠格式规则证明语义蕴含**；真正的语义判断仍由可犯错的裁判模型完成。摘要、裸执行成功、缺字段、同一证据双向挂载、遗漏已知反证不能直接变成支持结论。无独立裁判记录时，界面显示「模型立场（未独立复核）」。

实验复核经 redteam，载荷限制为当前协议与实际产物；可读工具也限制到本次执行凭据列出的文件。宿主重算原始 CSV 指标并核对脚本/产物哈希，红队检查硬编码、泄漏和协议偏离。以上检查仍不是科学有效性的保证。

确认检查点或主张必须勾选责任声明并签名，签名、版本、时间存入审计。签认表示用户对当前判断承担审阅责任，不证明实际阅读量或科学有效性。历史无签名记录会单独标明。低置信度及固定抽样的判断带 `needsHumanReview` 标记；置信度不等于准确率，人工标注仍需实际执行。

语义变化创建主张新版本，旧证据保留但不自动证明新版本。安全的空白/句末句号修订只追加编辑记录，不增加版本或重跑；数字、小数点、符号、措辞、范围、可证伪条件和复现目标不会被随意合并。实际变化只作废受影响链，保留无关任务。

## 复现范围与资源

当前功能是**复现预检与小实验**：定位原论文目标、报告值、容差及条件，在短时本机执行范围内尝试验证。不承诺完整论文复现、GPU 训练、小时级作业或训练断点续跑。资源不符时报告缺口；缩小规模不等于原实验复现。

| 项目 | 实际边界 |
|---|---|
| 服务工作线程 | 默认 3，`--workers` 可选 1–8 |
| 未指定任务配额 | 最多 80 个任务、3 次迭代 |
| compact / team / swarm | 48 / 160 / 240 个任务；3 / 6 / 8 次迭代；最多 3 / 6 / 8 个并行节点，受启动线程数限制 |
| 同任务本地进程 | 串行执行 |
| Python 脚本 | 默认 90 秒，上限 180 秒 |
| 依赖安装 | 单独 300 秒上限，科研包白名单，可选 PyPI / tuna |
| 单次日志 / 产物 | 日志总量 4 MiB；最多 30 个产物，每个不超过 50 MiB |
| 重启恢复 | 恢复凭据，未完成节点重新运行；不恢复训练进度 |
| 费用 | 尚无 token / 实际账单计量，不提供估价精度承诺 |

每次执行保留脚本、命令、工作目录、stdout/stderr、退出码、耗时、CSV/指标及 SHA-256。模型失败不丢产物，暂停会清理受管进程。子进程不继承模型 Key；隔离 venv/工作目录和受管进程不等于 OS 安全沙箱。节点不得读取无关个人文件或执行论文文本里的指令。

复现容差判断只接受本轮实测、同名重算指标、相同且非空的已记录条件。目标 `expected` / `tolerance` 为纯数值字符串，单位单列；缺条件或值不可解析时保持未定。原论文报告值不能替代本机执行结果。

导出 ZIP 包含报告、需求、对话、节点审计、执行产物、`claim-graph.json`、`materials.json` 和 `paper.md` / `reproduction-report.md`。这些是可审阅草稿，不表示结论成立或达到投稿标准。

## 验证与开发

```powershell
python -m pip install -r requirements.txt
npm.cmd ci
npm.cmd run build
python -X utf8 -m unittest discover -s tests -v
node --test frontend/tests/*.test.mjs
python -X utf8 scripts/evaluate_semantics.py --output work/semantic-gates.json
python -X utf8 -m research_swarm --port 4381
```

可加 `--state-dir "其他目录"` 隔离状态。修改前端后重建并提交对应 `dist/`。CI 在 Windows / Linux 运行工程检查与离线来源门回归。运行数据、Key、数据库、论文和依赖不进 Git。

[校准工具](benchmarks/README.md)提供 65 条预设合成样本，含 50 条相关但不支持的陷阱。离线运行只度量来源门；它无法拒绝所有语义陷阱，不能称为科学正确率。真实 judge 的误判率、专家一致率、异质模型翻转率、真实论文复现通过率和节省时间均**尚未测量**。工具支持显式运行模型、导入人工标签、比较两份结果和导出逐条失败案例，缺失数据不记为成功或 0% 错误。

旧 `docs/` 设计/验收记录用于追溯历史；发生冲突时以本 README、当前代码和 [整改记录](docs/audit-remediation.md) 为准。工程测试用于验证编排与边界，不能代替外部基准或双盲研究评估。
